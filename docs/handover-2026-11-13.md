## 2. 架构决策

### ADR 0178：会议是 run，不是服务

- 一场会 = `meetings` 一行 + 一个 director 的后台 run；
- 一次发言 = 频道里的一条消息（`meta.meeting`），`meeting_turns` 只存顺序与 run/message 指针；
- director 只做三个纯决策：`planTurns` / `assessConvergence` / `extractDecision`；
- 决议 `decisions` 是一等公民（状态/条件/反方/QC/负责人/验收判据/证据/`verified_at`）；
- 主席是人，不是模型：收敛由 director 提议、由人确认。

### 薄 fork 契约（`docs/design/thin-fork.md`）

1. 默认只加新文件；
2. 只碰七个「缝」，且只能是插入；
3. 不为适配而重构上游；
4. 每条缝标 `fork: meetings`，预算 ≤40 行插入；
5. 合并清单：`bun install` → `typecheck` → meetings/schema 测试 → `check:boundaries` → 数标记。

**当前实测：39 行插入，11 处标记，6 个上游文件。**

已验证的行为：

- `planTurns`：五种模式的席位顺序（含辩论交替、头脑风暴轮转、主持收尾只留主席）；
- `assessConvergence`：目标+覆盖度、轮次上限、主席叫停的优先级；
- `extractDecision`：主席最后一段作为决议，保留最强反方，没发言就不产出；
- `planNextStep`：逐席推进、全员说完收敛、无席位不假装收敛、已收敛不重放；
- `advanceMeeting`：在频道 @ 席位 agent、写 `meta.meeting`、`startOrJoinRun` 真的起了一条 run、turn 转 `speaking`、下一 tick 返回 `wait: speaking`；
- 权限：三个工具在 `access.test` 里有 label/description（英文+葡语），scope 映射齐全。

## 4. 未完成（按顺序）

1. **发言闭环**：agent 回复落库后，把对应 turn 标 `spoken`（当前停在第一个席位，`planNextStep` 永远返回 `wait: speaking`）。
2. **自动推进**：run 结束后触发下一次 `advanceMeeting`（可挂在 outbox 的 run 结束路径，或加一个 `meetings.tick` job）。
3. **主席确认**：收敛时给发起人一张确认卡；确认后写 `decisions`、生成纪要。
4. **行动项落任务**：`decisions` 的 `acceptance.criteria` → `createIssue`（复用 `issues.ts`），外部动作走审批。
5. **服务端路由**：`apps/server/src/routes/app/meetings.ts`（GET 列表 / POST 开会 / POST 同步），挂在 `app.ts`。
6. **Web**：`apps/web/src/routes/org.$orgId.meetings.tsx` + 侧栏入口（要同步 `packages/client` 与 `packages/engine` 的 sidebar 镜像，见下）。
7. **端到端**：本地起 Postgres（或 PGlite 服务器模式）+ `bun run dev`，手工跑一场会；本会话**没有做过**。

## 5. 风险与注意事项

- **AGPL**：fork 之后所有改动都在 AGPL-3.0-only 下；对外提供网络服务要开源改动并保留 “Based on agentes.chat…” 署名。这是商业决定，未拍板。
- **上游漂移**：上游节奏很快（本会话期间 4 天 157 个 PR）。任何超出七个缝的改动都会让合并变贵，按 `thin-fork.md` 执行。
- **迁移**：`0259_meetings.sql` 是我方未发布迁移，重建过一次（删掉重生成）；**合并上游后不要再改写已发布的迁移**。
- **循环依赖**：`meeting-advance.ts` 用动态 `import()` 加载 `messages`/`dispatch`，否则 `search.ts` 的 builders 未初始化就会报错。改这里不要改回顶层 import。
- **未端到端**：真服务没起过，路由/页面/闭环都没验证；不要把单测通过当成“会议能用”。
